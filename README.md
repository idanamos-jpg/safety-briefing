# תדריך בטיחות באתר — הוראות הקמה

אפליקציית רשת (ללא התקנה מחנות) עם שני עמודים:

| קובץ | למי | מה |
|---|---|---|
| `index.html` | מנהל פרויקט / מנהל עבודה | כניסה, אתרים + QR, יצירת תדריך, חתימות רצופות על הטלפון, סגירה, PDF, מייל, ארכיון וחיפוש |
| `w.html?s=…` | פועלים | נפתח מה-QR הקבוע של האתר: שפה → סיסמת אתר (נזכרת בטלפון) → תדריך היום → חתימה |

השרת: **Supabase** (חינמי לשימוש כזה) — משתמשים, מסד נתונים, הרשאות, ושליחת מייל.

---

## הקמה — פעם אחת (~20 דקות)

### 1. פרויקט Supabase
1. נרשמים ב-https://supabase.com → **New project** (אזור: Frankfurt / EU).
2. **SQL Editor** → **New query** → מדביקים את כל התוכן של `supabase/schema.sql` → **Run**.
3. **Project Settings → API**: מעתיקים את **Project URL** ואת **anon public key**.

### 2. מילוי `config.js`
```js
window.APP_CONFIG = {
  SUPABASE_URL: 'https://xxxx.supabase.co',
  SUPABASE_ANON_KEY: 'eyJ...',
};
```
(המפתח ה-anon נועד להיות ציבורי. ההגנה על הנתונים היא במסד עצמו — RLS.)

### 3. העלאה ל-GitHub Pages
1. ריפו חדש ב-GitHub (למשל `idanamos-jpg/safety-briefing`) → מעלים את כל הקבצים מהתיקייה הראשית (`index.html`, `w.html`, `app.js`, `worker.js`, `shared.js`, `styles.css`, `config.js`, `manifest.webmanifest`, `sw.js`, `icon-192.png`, `icon-512.png`).
2. **Settings → Pages → Deploy from branch → main / root**.
3. הכתובת תהיה: `https://idanamos-jpg.github.io/safety-briefing/`

### 4. הגדרות כניסה ב-Supabase
**Authentication → URL Configuration**:
- **Site URL**: כתובת ה-GitHub Pages מסעיף 3
- **Redirect URLs**: אותה כתובת

**כניסה עם Google (אופציונלי)**: Authentication → Providers → Google → מדביקים Client ID/Secret מ-Google Cloud Console (OAuth client מסוג Web, עם ה-Callback URL ש-Supabase מציג). בלי זה — כניסה באימייל וסיסמה עובדת.

### 5. שליחת מייל (אופציונלי — בלי זה הכול עובד, וה-PDF יורד ידנית)
1. נרשמים ב-https://resend.com, מאמתים דומיין (רשומות DNS לדומיין של החברה), יוצרים API Key.
2. מתקינים Supabase CLI ומריצים מתוך התיקייה:
   ```
   supabase login
   supabase link --project-ref <ref>
   supabase functions deploy send-briefing-email
   supabase secrets set RESEND_API_KEY=re_xxx MAIL_FROM="תדריך בטיחות <safety@your-domain.co.il>"
   ```
   (אפשר גם דרך הדשבורד: Edge Functions → Create function → להדביק את `supabase/functions/send-briefing-email/index.ts`, ואת הסודות ב-Edge Functions → Secrets.)

עד שזה מוגדר, דף התדריך הסגור מציג בכנות: **"שליחת מייל עדיין לא הוגדרה"**.

## שימוש יומיומי
1. **אתרים** → יצירת אתר + סיסמת פועלים → **QR** → **הדפסת שלט לאתר** (שלט עם QR והסבר ב-6 שפות).
2. **תדריך חדש** → אתר, תאריך, שעה, מנהל עבודה, נושאים, הערות, נמענים.
3. פועלים סורקים את השלט וחותמים — או **"חתימות על טלפון זה"** ומעבירים את הטלפון מפועל לפועל.
4. בדף התדריך רואים את החותמים (עם תמונות, מתעדכן כל 8 שניות) → שם + חתימת מנהל → **סגירת תדריך** → PDF נוצר ונשלח.

### 📚 ספריית תדריכים אישית
- **ספרייה ← תדריך חדש**: כותבים כותרת וסעיפים (שורה לכל סעיף), או מעלים קובץ **Word / טקסט**. השורה הראשונה בקובץ נהיית הכותרת.
- **תרגום אוטומטי לכל השפות**: ממלא ערבית, רוסית, רומנית, הינדית וסינהאלית. אפשר לתקן כל שפה ידנית לפני השמירה.
- ביצירת תדריך יומי מסמנים את התדריכים מהספרייה, לצד הנושאים המובנים או במקומם. הפועל רואה אותם בשפה שבחר.
- בתדריך נשמר עותק של התוכן, כך שעריכה בספרייה לא משנה תדריכים שכבר נוצרו.
- שפה בלי תרגום מוצגת לפועל בעברית.

הפועל רואה רק תדריך **מתאריך היום (שעון ישראל)** של האתר שסרק. כדאי שיוסיף את הדף למסך הבית ("הוספה למסך הבית") — מהיום הבא הוא נכנס ישר.

## הגנות שנאכפות בשרת (לא רק במסך)
- כל מנהל רואה רק את האתרים, התדריכים והחתימות שלו (RLS).
- סיסמת אתר נשמרת מוצפנת (bcrypt), לא נחשפת לאף משתמש, ונבדקת בשרת בכל קריאה, עם השהיה מול ניחושים.
- אותו שם לא יכול לחתום פעמיים על אותו תדריך (ללא תלות ברווחים/אותיות).
- אין חתימה בלי תמונה, בלי חתימה או בלי אישור השתתפות.
- חותמת הזמן נקבעת בשרת (לא בטלפון).
- אחרי סגירה: אין הוספה, שינוי או מחיקה של חתימות או פרטי התדריך. גם תדריך סגור לא ניתן למחיקה.
- התמונות נשמרות בטבלה מוגנת — רק בעל התדריך רואה אותן. ה-PDF שנשלח לנמענים כולל חתימות, לא תמונות.

## חשוב לדעת
- **התרגומים** (ערבית, רוסית, רומנית, הינדית, סינהאלית) נכתבו על ידי AI — יש להעביר לדובר שפת אם לבדיקה לפני שימוש אמיתי. הטקסטים נמצאים ב-`shared.js` (נושאים) וב-`worker.js` (ממשק).
- **הערות חופשיות** של המנהל לא מתורגמות — מוצגות לפועל כפי שנכתבו, עם ציון לכך.
- נוסח נושאי הבטיחות הוא נוסח בסיס — מומלץ שממונה הבטיחות יאשר אותו (עריכה ב-`shared.js`).
